## 界面预览

> 🖼 **图文手册**：完整界面截图与操作说明在 **[`docs/manual.html`](docs/manual.html)** ——
> 自包含单文件（截图内嵌），下载后浏览器直接打开即可；启用 GitHub Pages 后也可在线浏览。
> 该文件同时作为资产附在 [Releases](https://github.com/496793028/wg-web/releases) 中。

整个前端**零框架、零构建**，交互全部围绕「**卡片**」展开 ——
账号是卡片、目的地是卡片、目的地包还是卡片：**点开卡片就是授权，勾两下就生效**，
网关侧的放行规则与客户端 AllowedIPs 自动同步。深 / 浅双主题下，滑动高亮、渐变与发光动效保持一致。

- **VPN 配置** —— 每个用户一张卡片：姓名、VPN 地址、已授权目的地一目了然；
  黑名单模式（默认放行、勾选即禁止）用**鎏金**描边与徽标区分，全代理模式（全部流量经网关转发、外网走 NAT）用**淡紫**区分，双开时卡片光晕在两色间缓慢渐变（共振）。
- **目的地池** —— 「IP-端口池 / 目的地包」双标签滑动切换；
  条目协议支持 **TCP / UDP 多选**，一次授权两种协议一起放行；
  表单校验失败就地显示红光晕与原因文字，未保存改动会被拦截提示。
  **IP 与端口同样支持范围与批量写法**：IP 可直接填单机 `10.0.20.5`、**末位为 0 即按掩码授权整个网段**（`192.168.3.0` → `192.168.3.0/24`）、显式掩码 `192.168.3.0/26`、区间 `10.0.20.5-10.0.20.9`，并用逗号任意组合（`10.0.20.1,192.168.3.0-192.168.3.20`）；表单下方**实时预览**最终授权的网段与规模。区间会展开为**最小 CIDR 覆盖**——只覆盖你写的那一段，不会顺带放行旁边的主机。
- **账号管理** —— 按模块的「无权限 / 仅查看 / 可修改」三级权限，卡片右上角即见角色与状态。
- **访问追踪** —— 用户访问记录与管理员操作审计分页展示，竖屏自动转卡片。
- **移动端** —— 侧栏收为底部导航（滑动高亮），**长按卡片进入批量管理**，表格与卡片按屏宽自动切换形态。

## 它解决什么问题

VPN 开通之后，「**谁能连、能连到哪台机器的哪个端口**」往往散落在各网关配置里、靠口口相传，没有统一记录。一旦发生越权访问或泄漏，**难以溯源**。

本平台把这件事收敛到**一个带留痕、可审计的管理界面**里：

- **账号 / 角色 / 模块权限矩阵** —— 谁能进平台、能管哪类资源
- **目的地池（IP-端口）+ 目的地包（组合）** —— 把零散内网地址组织成可授权单元；端口支持 **留空=全部端口**、单端口、区间（`100-200`）与多段混用（`9,100-200`，中英文逗号均可）；**IP 支持同样的批量写法**：单机、**末位 0 即整段**（`192.168.3.0` 按掩码 `255.255.255.0` 记为 `192.168.3.0/24`）、显式掩码（`192.168.3.0/26`）、区间（`10.0.20.5-10.0.20.9`）与逗号组合
- **按真实姓名分配 VPN 账号 + 可视化授权** —— 谁可访问哪些目的地，一目了然
- **访问记录 + 管理员操作审计** —— 每一次新建连接、每一次后台改动都有留痕

## 核心特性

| 能力 | 说明 |
| --- | --- |
| **逐用户精细放行** | 每个用户绑定固定虚拟 IP（`/32`），网关按源 IP 精确放行到「某台机器的某个端口 / 端口区间 / 全部端口」，默认拒绝 |
| **WireGuard 密钥托管** | 后端生成 X25519 密钥对，**私钥经 AES-256-GCM 加密落库**；客户端配置一键生成（复制 / 下载 `.conf`） |
| **双模式 peer 落地** | `agent`（网关拉取，Web 无需 root）/ `local`（平台直写 `wg syncconf`，需 root） |
| **黑名单 / 全代理模式** | 每用户可独立开启 **黑名单**（默认放行、勾选禁止）与 **全代理**（全部流量经网关转发，内网仍受控、外网走 NAT 出口），两者可叠加；下发的客户端配置与网关规则自动同步 |
| **配套客户端 wg-companion** | 独立客户端应用（Windows / macOS / Android）：导入 `.conf` 即显示**用户名 / 授权网段 / 白名单·黑名单·全代理模式**，一键开关隧道（无需打开 WireGuard 官方程序），配置变更自动更新 —— 见 [wg-companion](https://github.com/496793028/wg-companion) |
| **VPN 账号（客户端登录）** | 每个 VPN 用户可开通登录账号（**用户名 = VPN 配置姓名**）：客户端用「用户名 + 密码」登录后**自动拉取并置顶显示自己的配置**，退出即删除。账号可**启用 / 停用**，未启用时口令可为空；启用空口令账号时要求输入密码，未输入则**自动生成**。口令经 **AES-256-GCM 加密落库**（需可回显给管理员转交本人，与私钥同一套主密钥），管理员可在账号二级页查看 / 修改 |
| **账号与配置一一绑定** | 「VPN 账号」与「VPN 配置」是同一条记录：**删除任一方即同时删除另一方**（含全部访问授权），删除前会明确警告 |
| **账号管理双 Tab** | 「账号管理」页支持滑动切换 **平台账号管理**（sys_account）⇄ **VPN账号管理**（vpn_account）；新账号创建、启停、改密、查密都在此完成，竖屏下同样为卡片式 |
| **授权双向对账** | 平台删除用户 → 网关侧 peer 自动移除，**不留僵尸 peer** |
| **全链路审计** | 管理员所有写操作落库（操作人 / 动作 / 对象 / 来源 IP）；用户访问记录可按人、目标、端口、结果、时间筛选（流日志需网关 `vpn-logship` 回传，参考最小实现见 `verify/vpn-logship-min.py`，不随正式发布分发） |
| **数据库可切换** | `DB_DRIVER=mysql`（默认，独立/远程库）或 `sqlite`（单机单文件、零依赖，用 Node 内置 `node:sqlite`）；业务代码只依赖方言层，不含任何库专有语法 |
| **飞书审批自动开通** | 对接飞书多维表格：审批通过后**自动建号 + 授权 + 回写账号密码**，并把凭据推送申请人飞书。支持**平台主动拉取**（无需公网入口）与**外部系统调用**两种方式，多人审批按首次结论锁定 |
| **企业级安全基线** | scrypt 口令哈希、服务端可吊销会话、登录失败锁定（连续 5 次锁 15 分钟，**超级管理员除外**）、全程参数化 SQL、CSRF 防护、HTTPS 就绪 |
| **零构建前端** | 纯静态 `index.html` + `app.js` + `styles.css`，双主题（深色 / 浅色），无打包步骤 |

## 架构

```
   控制面（本平台）                        数据面（网关）
┌──────────────────────┐          ┌──────────────────────┐
│  浏览器 UI           │          │  WireGuard (wg0)     │
│  Express 后端  8787  │  ① 授权  │  nftables per-user   │
│  MySQL  授权数据     │ ───────► │  规则（按源 IP 放行）│
│                      │ ◄─────── │  流日志 vpn-flow     │
└──────────────────────┘  ② 日志  └──────────────────────┘
```

- **① 授权下发**：网关上 `vpn-sync` 定时拉 `GET /api/gateway/grants`，把「谁能访问哪些 IP:端口」渲染成 nftables 规则并重载。
- **② 日志回传**：网关上需自行部署 `vpn-logship`（读 `/var/log/vpn-flow.log`，解析后 `POST /api/ingest` 推回平台；本仓库不随附该脚本与 systemd 单元）。

**信任锚**：WireGuard 在 hub 侧强制「用某 peer 公钥解密的包，源地址必须匹配该 peer 的 `AllowedIPs`」。因此网关上看到 `SRC=10.100.0.11` 就**确定是那个人** —— per-user 权限与审计由此成立。

## 快速开始

### 1. 配置环境变量

```bash
cp .env.example .env
```

**至少修改这几项**（详见 [部署前必读](#️-部署前必读)）：

```ini
DB_HOST=127.0.0.1
DB_USER=vpnapp
DB_PASS=<改成强口令>
ADMIN_INIT_PWD=<改成强口令>
INGEST_TOKEN=<改成随机长串>
WG_KEY_SECRET=<改成随机长串>
```

### 2. 初始化数据库

```bash
cd server
npm install
npm run init        # 建表 + 创建初始管理员
```

### 3. 启动

```bash
npm start           # → http://127.0.0.1:8787
```

或回到项目根目录，在已放置 `.env` 的前提下直接运行：

```bash
node server/server.js      # 与 npm start 等价，自动读取项目根目录 .env
```

### 4. 自检（可选）

```bash
cd server && npm run selftest
```

覆盖口令哈希、口令策略、会话令牌、SQL 参数化扫描、安全中间件等静态与单元检查，应输出 `26 通过 / 0 失败`。

> **生产部署请勿使用上述临时启动方式**，请改用 systemd 单元托管进程，并做好 MySQL 加固与 Nginx 反向代理（相关配置不在本仓库范围内）。

## 网关对接接口

两个**免登录、由 `x-ingest-token` 保护**的接口，供网关侧 agent 调用：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/gateway/grants` | 拉取「IP → 允许目标」授权清单（`vpn-sync` 用） |
| `GET` | `/api/gateway/peers` | 拉取 WireGuard peer 清单（`vpn-sync` 对账用） |
| `POST` | `/api/ingest` | 回传访问日志（`vpn-logship` 用） |

其余接口均需登录会话，并按模块（`account` / `dest` / `vpn` / `audit`）校验 `r` / `rw` 权限。

## 飞书审批集成

把飞书多维表格里的 VPN 申请，变成平台里的 VPN 账号：**审批通过 → 自动建号 + 授权 → 账号密码回写表格 / 推送给申请人**。

支持两种接入方式，在同一入口里切换：

| 方式 | 谁发起 | 适用场景 |
| --- | --- | --- |
| **平台主动拉取**（推荐） | 平台定时读表 | 平台部署在内网、飞书云端访问不到 —— 绝大多数情况 |
| **外部系统调用** | 飞书自动化 / 自建服务 `POST` 平台 | 平台有公网入口，或已有现成的审批系统 |

两种方式共用同一套字段映射、幂等规则与错误码。

### 1. 准备飞书应用

1. [飞书开放平台](https://open.feishu.cn/) → 创建**企业自建应用**
2. 「权限管理」开通：
   - `bitable:app` —— 读写多维表格（读申请、回写账号）
   - `im:message:send_as_bot` —— 给申请人发消息
3. 「版本管理与发布」创建版本并**发布**（权限变更必须重新发布才生效）
4. 在「凭证与基础信息」拿 **App ID / App Secret**

> 应用权限分「应用身份」与「用户身份」两套。本平台用的是**应用身份**（`tenant_access_token`，
> 有效期 2 小时、由平台自动续期），无需用户授权。

### 2. 准备多维表格

新建多维表格，至少包含这些字段（**字段名可以不同，在平台的「字段映射」里改即可**）：

| 平台字段 | 默认字段名 | 类型 | 必需 | 说明 |
| --- | --- | --- | :-: | --- |
| `request_id` | 申请编号 | 自动编号 | ✔ | 幂等键，同一单号只开通一次 |
| `applicant` | 申请人 | 人员 | ✔ | 取其中的 `open_id` 发消息，姓名用于称呼 |
| `username` | 期望用户名 | 文本 / 公式 | | VPN 账号名，留空则用申请人姓名 |
| `packages` | VPN目标 | 多选 | ✔ | 目的地包名（同名目的地池会一并授权） |
| `perm` | 权限模式 | 单选 | | 默认 / 全代理 / 黑名单，空=默认 |
| `status` | 审批状态 | 单选 | ✔ | 至少包含 **已通过** / **已驳回** |
| `note` | 用途说明 | 文本 | | 写入账号备注 |

可选的回写字段（存在才写，不存在自动跳过）：**用户名**、**密码**（文本）。

表单视图建议只让申请人填：邮箱 / VPN目标 / 用途说明；审批人、审批状态、权限模式由审批侧维护。

### 3. 平台侧配置

1. 顶栏 **外部连接配置** → 切到「平台主动拉取」→ **+ 新增连接**
2. 填 **App ID / App Secret / Base Token / Table ID**
   - Base Token：多维表格地址里 `/base/` 后那一段
   - Table ID：数据表地址里 `table=` 后的 `tblxxxx`
3. 点 **测试连接** —— 应返回「连接正常，可读 N 条记录」
4. 点 **试运行（不建号）** —— 只统计将被处理哪些单，确认申请人 / 目标 / 用户名都取对了
5. 把「主动拉取」改为 **启用**，间隔默认 300 秒

上线前建议先只留一条测试记录，跑通一单再放全量。

### 4. 权限模式

`perm` 字段决定账号形态，对应平台里的 `mode` + `full_proxy` 两个字段：

| 取值 | 效果 |
| --- | --- |
| **默认**（或留空） | 白名单：只放行授权目的地，**外网完全不通** |
| **全代理** | 内网仍按白名单，**外网全部放行**（经网关 NAT 出口） |
| **黑名单** | 授权清单变成「屏蔽清单」，**除清单外全通**（含整个内网与外网） |

黑名单的屏蔽清单不能为空 —— 空清单等于全放行，平台会直接拒绝（`1006`）。

### 5. 账号名规则

- 优先用 `username`；未提供则回退申请人姓名（兼容旧调用）
- 来自申请单的值按**不可信输入**处理：先转小写，再校验 `^[a-z][a-z0-9._-]{1,30}[a-z0-9]$`
- 保留字（`admin` / `root` / `system` / `administrator` / `operator` / `vpn` / `guest` …）一律拒绝
- 账号已存在时走**合并**：默认/全代理取授权并集，黑名单重置授权；但只有**创建者本人**（`owner_open_id` 相同）才能合并，否则返回 `1008`，避免填别人的用户名拿到别人的密码

### 6. 多人审批

平台把 **已通过** 与 **已驳回** 都视为终态：

- 谁先给出结论就按谁的结果处理，之后状态再被改成什么都不会改判
- 驳回会落一条 `code=2001` 的开通记录，锁定该申请单
- 精度取决于轮询间隔：以「平台第一次看到的状态」为准；若需要严格按**第一个审批人**，应在 Base 侧用自动化在状态首次变更时写入一个「审批结论」锁字段

### 7. 回写与通知

连接上有两个独立开关：

| 开关 | 作用 | 默认 |
| --- | --- | --- |
| **开通后回写表格** | 把用户名 / 密码写回申请记录 | 启用 |
| **发送飞书消息** | 把账号 / IP / 密码推送给申请人 | 启用 |

⚠️ 回写会把**密码明文**存进多维表格 —— 能看到这张表的人都能看到。不需要的话关掉即可，
或在 Base 侧用高级权限限制「密码」列的可见范围。

### 8. 外部系统调用（push 模式）

连接切到「外部系统调用」，把接口地址和 `X-App-Token` 填到调用方：

```bash
curl -X POST http://<平台地址>/api/open/vpn-provision \
  -H 'Content-Type: application/json' \
  -H 'X-App-Token: ext_xxxxxxxx' \
  -d '{
        "request_id": "VPN-0001",
        "applicant":  "张三",
        "username":   "zhang.san",
        "open_id":    "ou_xxxxxxxx",
        "packages":   ["测试环境"],
        "perm":       "默认"
      }'
```

返回：

```json
{ "ok": true, "code": 0, "message": "开通成功",
  "vpn_id": 12, "username": "zhang.san",
  "vpn_ip": "10.100.0.11", "password": "xxxxxxxx", "replayed": false }
```

> **业务错误也返回 HTTP 200**，须用 `code` 判断；只有令牌无效才是 `401`。
> 这样飞书自动化的 HTTP 节点（只认 2xx）能拿到明确原因。

### 9. 返回码

| code | 含义 |
| --- | --- |
| `0` | 开通成功 / 已合并 / 幂等重放 |
| `1001` | 缺少申请单号 |
| `1002` | 缺少申请人 |
| `1004` | 申请的目的地在平台不存在 |
| `1005` | 目的地名称存在多条（池重名），无法确定授权对象 |
| `1006` | 黑名单模式未指定屏蔽目的地（空清单等于全放行） |
| `1007` | 用户名不合法（格式 / 保留字） |
| `1008` | 账号已被占用且无法确认归属 |
| `1009` | 内部错误 |
| `2001` | 审批驳回（拉取侧记录的终态） |

### 10. 安全说明

- **App Secret** 经 AES-256-GCM 加密落库，接口只返回「已配置」而不回显
- `/api/open/*` 只用 `X-App-Token` 鉴权，因此**豁免 CSRF 头校验**（无 Cookie 会话，不存在 CSRF 风险）
- 幂等重放从库里解密原口令返回，**不存明文**；密码只在响应里出现一次
- 账号名带白名单与归属校验，防止冒用他人账号名

## ⚠️ 部署前必读

**1. 初始管理员口令：默认在网页上设置，源码中没有任何固定默认口令**

`.env` 的 `ADMIN_INIT_PWD` **默认为空**。留空时，`npm run init` 会以「口令未设置」状态创建 `admin` 账号，
**首次打开平台会自动进入初始化页**，由你在网页上设定口令。

若你选择在 `.env` 中预设（适合自动化部署），请务必换成自己的强口令；**预设后平台启动即不会弹出网页设置口令页，直接用该口令登录**。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ADMIN_INIT_PWD` | 空 → 走网页初始化 | 若填写，需 ≥6 位且含大小写字母与数字 |
| `DB_DRIVER` | `mysql` | `mysql`（默认，可独立部署）或 `sqlite`（单机零依赖） |
| `DB_FILE` | `server/data/vpn_ctrl.sqlite` | 仅 `DB_DRIVER=sqlite` 时使用，自动建目录 |
| `DB_PASS` | 空 | 数据库口令，**务必设置**（仅 mysql） |
| `INGEST_TOKEN` | 空 | 网关推送鉴权，**生产必须设置** |
| `WG_KEY_SECRET` | 空 | 私钥加密主密钥 |
| `WG_CLIENT_DNS` | 空 | ⚠️ **黑名单 / 全代理模式必设**：隧道内 DNS，需填隧道可达的公共解析（如 `223.5.5.5,119.29.29.29`）。留空时全量进隧道的模式下客户端仍用本机 DNS，查询会被网关默认拒绝，表现为"握手成功但域名全部解析失败" |

> ⚠️ **完成初始化之前，不要把平台暴露到公网。**
> 在口令设定完成前，任何能访问到该服务的人都可以抢先调用初始化接口设定口令。
> 建议初始化后刷新页面确认已回到正常登录页。

**2. 备份 `server/.wgkey`**

若未在 `.env` 中设置 `WG_KEY_SECRET`，平台首次运行会自动生成 `server/.wgkey`。
**丢失它 = 所有历史私钥无法解密**，只能给全部用户重新签发密钥与配置。

**3. `ADMIN_INIT_PWD` 仅在 `npm run init` 首次建号时生效**，之后修改 `.env` 不会影响已有账号，
需在「账号管理 → 重置密码」中修改。

**4. 本项目是控制面，不是数据面**

平台负责密钥 / 授权 / 审计，**不含流量转发代码**。真正生效的访问控制需要网关侧 `vpn-sync` / `vpn-logship` 配合（相关脚本与 systemd 单元需自行准备，本仓库不随附完整部署手册）。

**5. HTTPS 部署注意**

经 Nginx 终止 TLS 时，必须设置 `COOKIE_SECURE=1` 并传递 `X-Forwarded-For`，否则会出现「登录后一刷新就掉线」或「审计来源 IP 全部失真」。

## 配套客户端

**[wg-companion](https://github.com/496793028/wg-companion)** —— 本平台的独立配套客户端（**Windows / macOS / Android**）：

- 导入平台下载的 `.conf` 后，界面直接显示 **真实姓名 / 被授权网段 / 授权模式**（白名单 · 黑名单 · 全代理）——
  平台在配置首行内嵌 `wg-meta` 元数据（base64 注释行，标准客户端完全兼容）；
- **一键开关隧道**，无需打开 WireGuard 官方程序：Windows 走官方 `wireguard.exe` 服务化接口、
  macOS 走 `wg-quick`、Android 内嵌官方 GoBackend；
- **自动更新配置**：权限变更后重新下载同名配置覆盖，客户端自动感知并在隧道在线时自动重下发；
- 界面与本平台同源设计语言（淡紫 × 鎏金），带完整入场 / 点击 / 连接动画。

> 权限变更后「重新下载配置 → 客户端自动生效」的完整闭环即由本平台 + wg-companion 构成。
